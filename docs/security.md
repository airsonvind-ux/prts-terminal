# 安全边界

## 信任模型

- **LLM 不可信**：模型只能提出工具调用，不能直接执行命令、读写任意路径或修改审批策略。
- **前端不可信**：前端可以展示状态，但权限判断、路径解析和执行必须由 Rust 层完成。
- **外部更新源不可信**：清单和安装包必须验签；签名版本与清单版本不一致时拒绝。
- **本地数据是用户资产**：会话、记忆、凭据和附件不因更新、压缩或启动失败而被静默覆盖。

## 控制面

### 工具审批

需要审批的调用会生成审批卡。拒绝、取消和超时会形成明确的工具结果，不会让 Agent 误以为执行成功。

### 命令执行

- 默认使用受限令牌
- 通过 Job 对象约束子进程生命周期
- 只对工作区和必要临时目录临时放行 ACL
- 超时和取消会终止进程树

### 路径

- 文件工具经过路径守卫，阻止目录穿越和受保护路径写入
- 工具的工作区根与用户的配置一致，不信任前端传入的任意路径

### 凭据

API key 使用本机用户绑定的加密存储；设置文件只保存掩码或引用，不保存明文。

### 更新

- 清单必须签名
- 下载前检查磁盘空间
- 安装前再次检查活跃 turn 和 MAA 任务
- 失败阶段区分检查、下载、磁盘和安装，避免把不同问题报成同一种错误

### 前端内容

- Markdown 渲染经过清洗
- 外部链接通过受限打开接口处理
- Tauri 能力按窗口最小化配置
- CSP 应覆盖实际加载面，不能长期留空

## 报告问题

安全问题不要公开提交 issue。请通过仓库维护者提供的私密渠道报告，并附上复现步骤、影响范围和版本号。不要在报告中粘贴真实 API key、会话内容或本机路径。
