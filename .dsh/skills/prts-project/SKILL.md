## 开发流程规范（spec-first + 测试先行）

1. **spec-first**：每个开发阶段/模块先建 spec 文档（目标、交付标准、依赖链），再做针对性开发。
2. **测试方法必须在开发前与用户确认**：每份 spec 必含「测试方法 / 验收标准」一节；测试内容与测试方法**在开发前与用户确认**——阶段目标不同，测试方法与标准也不同，不存在统一标准，确认后才交由 LLM 开发。
   - 有客观判定标准的（数值/计算类：知识库精确性、正演/反演推演、工具查询等）→ 用户编写测试题，验证处理链路 + 处理结果。
   - 偏主观/抽象、无固定测试题的（策略分析、UI 观感等）→ 与用户讨论确定测试/验收方式。
3. **测试集作为项目资产**：可客观验证的测试题、陷阱题、ground truth 随项目版本化、持续积累。

## 轮次执行流程（主 agent 控制 + 子 agent 执行 + 审查）

> ⚠️ **人工逐步确认，不是自主长跑**：每步只做用户当前要求的，输出后**立即停止并等待用户回复**；用户回复前不得开始新一轮思考或工作。**不要使用 goal 工具（create_goal 等），不要创建任何自动续跑目标。**

1. **确定工作内容**：每轮开始，用户先确定本轮目标与范围。
2. **了解现状 + 讨论方案**：主 agent 读项目文档了解现状，与用户讨论实现方案（含测试方法，见上方规范），确认后才动手。
3. **派遣子 agent 执行**：具体开发由主 agent 调用子 agent 完成；主 agent 负责拆解、派发、汇总。
4. **代码审查**：开发完成后由主 agent 审查子 agent 的产出，确保项目质量。
