## 关卡数据的组成

一个关卡的完整数据由五部分组成：

- **地图**：关卡的地块网格，表达"地形长什么样、能不能走、能不能部署"
- **路线**：敌人行动的预设约束，表达"敌人从哪里出现、要经过哪些点、在哪里结束"
- **波次**：出怪的时序关系，表达"敌人什么时候出现、出现多少、是否随机"
- **预置单位**：关卡预设的单位，表达"开局已在场上或可供部署的干员/装置"
- **关卡符文**：关卡预设的、满足特定条件时生效的关卡数值修正或机制调整

其中地图描述静态空间，路线与波次描述动态行动，预置单位与符文是工具用于描述附加设定。

## 地图：地块网格的三个维度

地图数据是一个网格，每格是一个地块。三个视图是同一网格在不同维度上的投影，格子位置一一对应：

- **地块名网格**：最原始的数据，每格一个地块名（tileKey），唯一确定该地块的类型
- **通行视图**：表达"哪些敌人能走"，由地块的通行掩码派生
- **部署视图**：表达"哪些位置能部署"，由地块的部署类型派生

读图时以地块名网格为基准定位，用通行/部署视图回答"能不能过、能不能放"。
地图的最外围通常是不可部署的偏装饰性地块，通常与作战关系不大。

### 坐标

- 坐标写作 `(x, y)`：x = 列（自左向右，0 起），y = 行（自下向上，0 起），与偏移量的坐标方向一致
- 地图按行打印，第一行是地图顶部（最大 y），行号从上到下递减

### 通行视图的特殊符号地块

通行视图中部分地块以字母/符号标注而非通行符号，其通行与高度属性统一：

| 地块 | 符号 | 高度 | 通行 | 部署 |
|---|---|---|---|---|
| tile_start 侵入点 | S | 低地 | 全通行 | 不可部署 |
| tile_flystart 空袭侵入点 | F | 高台 | 仅飞行 | 不可部署 |
| tile_end 保护目标 | E | 低地 | 全通行 | 不可部署 |
| tile_telin 通道入口 | [ | 低地 | 全通行 | 不可部署 |
| tile_telout 通道出口 | ] | 低地 | 全通行 | 不可部署 |

- 侵入点（tile_start）为地面出生点，空袭侵入点（tile_flystart）为高台上的飞行单位出生点
- 保护目标与通道出入口均为低地全通行，仅承担功能（扣生命 / 传送）

### 特殊地块查表

基础地块（forbidden / road / start / end / wall / floor）语义固定；其余地块类型繁多（如地穴、热泵通道、冰面等），部分具有特殊效果（伤害、传送、增减益）。


## 路线：敌人行动的预设约束

路线是关卡预设的行动约束，由六部分构成：

- **行动方式**：WALK（地面移动）/ FLY（飞行移动）
- **起点**：敌人出现的位置，输出为方括号坐标 `[(3,5)]`，可带生成偏移（spawnOffset）与生成随机范围（spawnRandomRange）
- **终点**：行动结束位置，输出为方括号坐标
- **生成随机范围**：起点附近的随机生成范围
- **生成偏移**：起点位置的偏移
- **路径点事件列表**：敌人依次执行的检查点序列，各类型的语义见《行动指令类型枚举》

### 路径点事件的输出形态

检查点按类型与字段实际值呈现为三种形态。附加信息按序为：类型名（仅非移动类型出现）、时间（仅非零出现，如 `20.0s`）、偏移（仅非零出现，如 `offset=(0.5,0)`，即该检查点的目标点偏移）：

- **纯坐标**（如 `(6,3)`）：移动类检查点（MOVE）且无时间与偏移
- **坐标 + 附加信息**（如 `[(6,35),离开传送]`、`[(6,3),20.0s,offset=(0.5,0)]`）：坐标有意义的类型（移动类目标点、传送落点等）的非默认形态
- **纯语义**（如 `[停驻·计时,275.0s]`、`[停驻·计时,20.0s,offset=(0.5,0)]`）：坐标无意义的类型（停驻类/进入传送/警报等），不含坐标，可带时间与偏移

路线是预设约束，敌人沿路线经过各路径点时的具体轨迹由寻路与移动机制决定，路线本身不描述轨迹。路线被波次中的组引用。

## 波次：出怪的时序关系

波次描述敌人出场的时序，结构为 **波 → 段 → 组** 三层：

- **波**：一个完整的进攻阶段，可带波前延迟（preDelay），且仅波层存在波后延迟（postDelay）属性
- **段**：波内的子阶段，可带段前延迟（preDelay）
- **组**：段内的基本调度单元，描述一次出怪，字段为行动类型、实体、数量、延迟、间隔、路线索引，并可带随机组标识

### 时序规则

每一层的时间构成 = preDelay + 内部时间轴（仅波层存在 postDelay 属性）：

```
波:  preDelay(波) + 波内段时间轴 + postDelay
  └─ 段:  preDelay(段) + 段内组时间轴
       └─ 组:  preDelay(组) + N × 间隔（数量 > 1 时生效）
```

计时基准：

- **波级 preDelay**：以本波自身起点为基准，波间相互独立
- **段级 preDelay**：以本段自身起点为基准，段间相互独立
- **组级 preDelay**：以"段的组时间轴起点"为基准。段内组时间轴起点 = 段起点 + 段级 preDelay，同一段内所有组共享这一基准，组间 preDelay 呈递增关系

衔接规则：

- **段间衔接**：fragment[n] 的起点 = fragment[n-1] 内最后一批敌人刷出时刻；fragment[n].preDelay 相对自身起点独立计算，前一段结束只决定后一段何时开始
- **波间衔接**：wave[i+1] 的起点 = wave[i] 内最后一批敌人刷出时刻 + wave[i].postDelay
- **不计算跨波绝对时刻**：波次按顺序推进，前一波敌人未全部刷出不会开始下一波
- **间隔仅在数量 > 1 时生效**：第 n 次刷出时刻 = 组 preDelay + n × 间隔（n = 0, …, 数量-1）
- **仅考虑生成时刻**：时间轴只计算刷出时间点，不含刷出后的移动、特效等事件

注意：数据中的时序是设定参数，实际表现受引擎影响可能与设定略有差异（如间隔实际表现可能晚 1~2 帧），解读时应作为参考设定而非精确事实。

### 随机组

组可带随机组标识，四个字段共同定义随机性：

| 字段 | 语义 |
|---|---|
| 随机组 key | 随机选择池标识。非空时该组属于一个随机池，每局从池中按权重选出一个 option |
| 包 key | 打包键。同一段内相同包 key 的组捆绑为一个不可拆分的 option，选中时一并触发（用于生成+显示路线成对绑定等） |
| 权重 | 整型权重。option 被选中概率 = 该 option 权重 / 同池所有 option 权重总和。权重为 0 的组不作为独立 option，但可作为包成员随包触发 |
| 隐藏组 | 非空时默认不激活，只有对应隐藏组被外部条件激活后才参与选择；null 表示始终可用 |

分组解析遵循**单层扁平竞争模型**，以单个段为处理单元：

1. **收集随机组**：随机组 key 非空 → 归入对应池；key 空但包 key 非空且同段存在同包 key 且有 key 的组 → 归入该池；两者皆无 → 固定刷出，不参与随机
2. **按包 key 形成 option**：池内组按包 key 分组，每个唯一包 key 形成一个 option。若池内所有组包 key 相同（典型为全空），则每个带 key 的组各自为一个 option 直接竞争；若存在多种包 key，则每个包下的全部组打包为一个 option，包之间竞争
3. **权重选择**：一个池内所有 option 按权重竞争，选中概率 = 该 option 权重 / 同池权重总和。option 含多个组时全部触发；选中空 option 则不刷出任何敌人

### 分支

分支是独立于波次的附加调度，结构与波次的段一致（段内为组列表），在特定条件触发时叠加行动。分支引用的路线与波次引用的路线是两套独立编号，不可混查。分支触发条件不在关卡数据中。例如在集成战略模式中，关卡通常会有专门的隐藏波次，如“鸭爵和他的雇员们”（概率生成）等

## 预置单位：关卡预设的单位

预置单位按两个维度划分四类：

- **实例 vs 卡片**：实例是开局已在场上的单位（带坐标与朝向），卡片是可供玩家部署的备选单位（带初始数量）
- **干员 vs 装置**：干员有精英化阶段与技能概念；装置无精英化与技能概念，仅有等级

## 关卡符文：关卡机制修正

关卡符文是关卡预设的、满足特定条件时生效的数值修正或机制调整（如紧急难度下的敌方攻击力倍率、生命值倍率、部署条件等），按难度分组生效，对应于stage表中的情报，level表中的关卡符文则为json文本，仅用于保底的语义对照。分组键与数值语义见《地图与敌人行动表结构》。
