## 计算流水线

战斗内所有实体（干员、敌人、召唤物等）的属性值沿固定流水线计算：

原始属性 → 符文运算 → 基础属性 → 修饰器运算 → 实际属性

- **原始属性**：数据文件直接定义的数值。干员的数据基础值计入信赖、潜能、模组加成，作为入关计算的起点（即下文“关卡外基础数值”）；敌人无此环节，数据值即输入
- **基础属性**：关卡外基础数值经过符文运算、取上下限后的数值。部分机制（如卫戍协议盟约）以此为判断标准
- **实际属性**：基础属性经过修饰器完整处理后的数值，最终呈现给玩家，绝大部分机制以此为判断标准
- **属性上限/下限**：由属性类型定义，个体的上下限可被部分游戏机制更改，默认上下限见「数据参考」分类

## 关卡外基础数值

关卡外基础数值 = 数据文件基础值 + 信赖加成 + 潜能加成 + 模组加成

干员资料页显示的面板数值即关卡外基础数值（社区常以“白值”称呼，本文统一使用关卡外基础数值），进入关卡后的所有属性变化都以它为起点。

## 符文运算（入场前）

突袭/紧急作战条件、部分集成战略藏品等效果在进入关卡时修改干员/敌人的基础数值，属于符文运算环节（分为关卡符文与藏品符文两种）。计算公式、叠加顺序与「局外加成/局内加成」的区分见《符文运算》条目。

## 修饰器运算（战斗中）

技能、天赋、局内 buff 等效果以修饰器（AttributeModifier）形式作用于属性，共四类：

| 类型 | 运算方式 | 典型描述 |
|:--|:--|:--|
| 直接加算 | 对基础数值加算固定数值 | 攻击力+100、防御力-220 |
| 直接乘算 | 对直接加算完成后的结果乘算 | 攻击力+200%、防御力+12% |
| 最终加算 | 对直接加/乘算完成后的结果加算 | 鼓舞效果 |
| 最终乘算 | 对其余三类完成后的整体结果乘算 | 防御力-70% |

### 同类叠加规则

除最终乘算外，同类修饰器之间均为加法叠加：

- 直接加算结果 Dp = p1 + p2 + ... + pn
- 直接乘算结果 Dt = t1 + t2 + ... + tn（**求和，非叠乘**）
- 最终加算结果 Fp = p1 + p2 + ... + pn
- 最终乘算结果 Ft = t1 × t2 × ... × tn（**叠乘**）

最终乘算的负值修正：组成结果的任意一项小于 0 时，该项补正为原数值+1。例：防御力-70% 的实际乘算系数为 -0.7+1 = 0.3。

### 核心公式

最终属性 Af = Ft × [(A + Dp) × (1 + Dt) + Fp]

- A 为基础属性（关卡外基础数值经符文运算后）
- 若 (1 + Dt) < 0，则 (1 + Dt) 补正为 0

### 语义判断方法

判断某效果属于四类中的哪一类：

1. **看数值形式**：固定数字（+100、-220）→ 加算；百分比（+100%、-70%）→ 乘算
2. **看效果性质**：常规属性修正（大多数技能/天赋）→ 直接加/乘算；鼓舞效果 → 最终加算；减益效果（对敌方属性的削弱）→ 一般为最终加/乘算

例：假日威龙陈三技能专三："攻击力+100%"为直接乘算；"地面敌人经过时移动速度-45%"为最终乘算；"防御力-220"为最终加算。

干员技能的具体运算类型以数据库干员备注标注为准，语义判断仅为辅助手段。

## 局内 buff 与藏品符文的区分

集成战略等模式中的藏品效果按计算体系分两类：

| 社区叫法 | 本系统叫法 | 计算体系 | 生效时机 |
|:--|:--|:--|:--|
| 局外加成 | 藏品符文 | 符文运算（入场前修改基础数值） | 进入关卡时 |
| 局内加成 | 局内 buff | 修饰器运算（与技能/天赋同类叠加） | 战斗中满足条件触发 |

判断藏品效果归属的主要依据是能否在关卡外稳定达成，存在特例，以游戏内实测为准。

## 取整规则

- **默认规则**：四舍六入五成双。小数部分 <0.5 舍去，>0.5 进位，恰为 0.5 时取两侧整数中的偶数（7.5→8，6.5→6）
- **规则不可绝对化**：游戏内不同计算可能采用不同规则，当结果恰好落在 x.5 时需注意，并以游戏内实际数值为准
- **取整时机**：进入游戏时的基础数值取整；修饰器计算后的属性显示时取整；中间运算过程一般不取整（实际属性值存在小数，显示时取整，但计算时不取整）
- 推演结果与游戏实际差 1~2 点时，问题关键可能就在取整规则

## 数值验证注意事项

**待部署区干员卡片面板不可靠**，原因有两个层面：

1. **天赋显示不稳定**：部分天赋的加成不显示在卡片上（例：黑角天赋 +12% 防御显示生效，卡片 355→398；陈天赋 +5% 防御不显示，卡片保持 380）
2. **计算方式错误**：卡片对同类直接乘算采用叠乘并分步取整，正确算法是同类求和后单次取整

实例（黑角）：生命关卡外基础数值 1760、天赋 +12% 时卡片 1971（1760×1.12=1971.2 取整，正确）；编入年（生命+16%）后卡片 2286（1760×1.12×1.16 分步取整，错误），部署后面板 2253（1760×(1+0.12+0.16)=2252.8 取整，正确）。

**结论：一切以部署后的干员面板为准。**
