# 数值计算

## 核心原则

- 流程规范性优先：先明确计算目标与场景假设，再按流程推演，不边算边补
- 假设必显式：描述无法完全确定的部分，以假设补全并声明；事实陈述与假设推断分开呈现
- 等效优先：面对不确定量，先寻找可假设的等价量（自由度去除），而非放弃计算或硬算。这是本 Skill 的核心方法

## 不确定性认知

游戏实际表现与设定值之间存在帧级偏差，来源多样（攻击动画、弹道生效时点、皮肤差异等）。计算输入来自数据库与知识库的设定值，无法获取游戏实际环境细节，因此理论计算只能得到理论值。理解这种偏差的存在，不臆测具体值，用假设与等效覆盖可能区间。这是等效、假设与演绎的合理性来源。

## 复杂度评估

开始计算前，通读问题描述与数据库备注，判断复杂度，不做保证。确定性离散条件（可枚举的分支，如目标类型）与窗口内恒定的状态变化不增加复杂度档位；概率、动态演化状态、多量耦合才计入：

- 简单：单一计算单元，无概率、无动态演化状态。确认关键量与单次结果即可，流程可精简
- 中等：多个计算单元，不确定量不多且彼此无复杂耦合，利用等效与假设可快速计算出一两个预设参数下的解
- 复杂：不确定量多且相互缠绕，解空间庞大，简化后仍存在多个参数，如存在多种概率的耦合。先等效简化，给出特定参数组合下的解，指出复杂度来源，并给出精细计算的算法思路（模拟、状态模型或分解算法），不强行一次算准

## 工作流程

标准的工作流程按以下五层依次执行。计算启动前，按任务涉及机制阅读"相关知识条目"中对应条目，读够即停。

### 第一层：问题解剖

把用户问题与技能/机制描述、数据库备注一次性拆解为独立计算单元，拆完再进入下一层，禁止边算边补。技能备注是描述文本的第一补充源，包含碰撞、转向、判定时点等欠缺机制，先读备注再建模。天赋通常是是与干员属性密切相关的重要信息，不要遗漏。

每个计算单元记录：触发时机（每次攻击、每秒、开启时、持续、事件触发）、作用对象（主目标、范围、特定条件）、数值构成（类型与倍率）、每击段数、生效条件。召唤物、弹道、地形效果等额外行为各自独立成单元。特殊措辞（至少、至多、额外等）可能隐含特殊机制，以备注与知识库解释为准。

计算目标在特殊技能形态下可能不是天然单一的概念：明确"总伤"等目标量在本技能语境下的定义形态（单次触发、单单位生命周期、全技能总量），定义不清时先声明定义再计算。无限时长或永续形态下，默认以速率口径（DPS/HPS）为目标量，总量口径需指定时长。

计算窗口来自用户指定时长、技能持续期、循环周期或资源耗尽点（弹药制），窗口形态不同则组织方式不同；文本未给出时长时参数化处理（记为 D，可枚举典型值）并声明。资源制技能先声明资源初始场景（默认待部署区无棋子、弹药满）。

技能、天赋等文本表述为自然语言，对于描述文本中的绝大多数不清晰，博士一句话就能澄清，及时询问是好习惯，能省去大量冗余的思考，你的算力应当集中在后续的推演分析上，不要让文本解析浪费你的算力与博士的时间。

### 第二层：场景假设

识别影响计算结果的语义缺口：描述无法确定的部分，如空间行为（弹道命中次数、地形影响）、时序行为（前摇、阻回、第一发时点）、条件性增益的成立条件、资源初始状态（待部署区、弹药存量）。对每个缺口选择处理方式：

- 场景枚举：给出典型场景的计算结果（最高、最低、默认）
- 参数化假设：识别决定结果的核心量，以假设值参数化，给出不同取值对应的结果。优先选择离散、可观测、有理论锚点的等价量（如攻击次数：总结果 = 次数 × 单次结果，次数是宏观可观测量；帧数是微观量，不可观测且受环境偏差影响），将多个自由度坍缩为一个
- 取舍：与核心目标弱相关、无法确定且无等价量可用、影响方向可声明时，省略该量，声明未计入与影响方向，可附单次量供参考
- 条件性增益（"当 X 时"的加成）取值时，显式声明条件成立的假设；修饰符的组合方式（提升至/提升/加算/乘算）无法确认时，按最合理解读假设并声明

选择默认假设并声明。不确定时优先假设并继续推演；用户明确要求精确场景时，按用户指定的条件执行。领域事实无法确认时，标注"该假设待知识库确认"及其对结果的影响方向。

### 第三层：行为模拟

窗口内的数值计算是时间问题，按周期分解组织：

1. 识别周期单元：从描述中找周期信号（"每次攻击""每 X 秒"），列出窗口内的周期单元与一次性事件
2. 模拟单周期：对每个周期单元模拟一次完整行为，含空间过程（弹道、地形效果）的文字化推演
3. 确定周期数：以攻击行为为例，次数可以计算为窗口时长除以实际攻击间隔（帧对齐后），再按四舍五入处理（攻击存在前摇，在窗口结束前0.01秒开始攻击，会因为窗口结束而被取消，按照四舍五入取整处理是稳健方法，因为无法确定最后一击是否会被取消），规则见《伤害计算基本公式》；攻击的实际时序伴随动画与判定过程，PRTS 没有精确时序的观测途径，因此该结果为参照基准，若用户提供了测得或参考的帧级时序，按用户数据精确计算；间隔以数据库返回值为基准，注意标定值与实际值可能存在帧级偏差。实际次数可能因动画、前摇、施放等现象与基准存在偏差，不尝试建模未知现象，在结果中声明偏差可能，用次数参数化覆盖（N±k 分别对应结果）
4. 叠加与边界：单周期结果乘以周期数，加上一次性事件；单独检查窗口截断的尾周期、开启瞬间的事件与结构性时间占用（施放、阻回）

周期成立的前提是行为固定：地形、攻速、buff 在窗口内不变。状态变化时按段拆分，段内周期化，段间独立。

无攻击循环的形态（事件触发、召唤物放置、弹药制）以事件计数组织：结果 = 单次事件结果 × 事件次数，事件次数是核心自由度；资源制技能的总伤按资源转化链组织（资源量 → 产出数 → 单次结果），资源量受上限、溢出、空间约束修正时先演算数量流，时间维度按操作节奏参数化。空间运动类效果（如剑气、电流、弹道）统一坍缩为命中次数：次数可由空间推理（速度、周期、判定时点）估算或直接参数化，并声明等效的粗糙度，承认大幅偏差的可能性。

永续或长窗口形态区分稳态与瞬态：稳态取满状态结果（如累积加成满层），瞬态事件（首击、启动期）单独声明或说明其长窗口摊薄。

### 第四层：确定与期望分离

概率效果先确认结算粒度（按攻击或按事件）与同轮多事件的独立性，再按期望计算：期望次数 = 概率 × 窗口时长 × 触发频率；随机选中类效果按选中概率分配期望。汇报时确定部分与期望部分分列，不混为单一数字，需要时给出上下限。

累积触发类效果（元素损伤爆条等）按期望累积逼近触发时机；结果依赖目标数量时，按数量分段或参数化，所有目标共享同一阶梯。目标量为伤害/输出时，控制效果（晕眩、停顿等）不计入结果，单列声明其附加价值。

### 第五层：推演记录

按以下结构组织汇报：

- 计算目标与场景假设：假设清单集中声明，含默认口径、条件性增益的成立条件与资源场景
- 计算单元与结算步骤：每步引用知识条目与查询结果
- 确定结果与期望结果分列
- 结果与假设绑定：在此假设下结果为 X；核心量取其他值时结果为 Y
- 理论值边界：只声称理论值，声明可能造成偏差的实际现象（帧级偏差、施放动作）与影响方向
- 简化声明：采用简化模型时声明省略了什么、结果偏大还是偏小

## 相关知识条目

在开始计算之前，需要先阅读相关的知识条目，确保自己对于计算机制的理解：
- 《属性计算机制》：属性流水线与修饰器运算。修饰符组合、属性加成计算时阅读
- 《伤害计算基本公式》：倍率、伤害公式、攻速与帧对齐、取整规则。伤害结算、攻速与次数计算时阅读
- 《符文运算》：rune 与局内 buff 的区分与叠加规则。涉及模式加成或藏品时阅读
- 《鼓舞与源实体机制》：涉及鼓舞类效果时阅读
- 《集成战略》导览：肉鸽场景先读导览定位主题，再读对应主题条目的难度加成节
- ...

## 默认口径

用户未指定养成条件或场景时采用以下默认值，并在汇报中显式声明：

- 干员：最高精英化满级、满信赖、0 潜、首个模组满级、技能最高级
- 敌人：计算目标在干员侧且用户未指定敌人时，不纳入敌人参数，仅声明防御/法抗等对结果的影响关系，用户指定或目标本身要求时纳入
- 多目标：默认按单目标结果 × 目标数呈现，目标数参数化并注明
- 肉鸽：场景判定为集成战略且用户未指定难度时，默认考虑幕后加成与难度加成（最高难度）；关卡符文、藏品、特殊条件等其他规则默认不考虑，用户明确指定才纳入

属性数值一律以查询工具返回为准。

## 汇报规范

汇报给出关键计算步骤与依据（公式来源、数据来源），显式声明所有未由用户指定的默认口径与场景假设。结论引用假设时带假设标记，事实陈述不掺假设。采用理论值与简化模型时，主动声明偏差来源与影响方向；复杂问题指出其复杂性，给出精细计算的算法思路。陈述自身行为只依据对话中实际发生的内容。
