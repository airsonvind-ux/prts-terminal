# 行动推演

## 一、知识学习指引

行动推演涉及的知识分散在若干条目中，按域阅读，读够即停。条目给出原理指导与定性结论，精确数值与坐标由模拟工具给出。

### 行动方式

- 条目：《敌人行动与移动机制》行动方式节
- 用途：敌人行动方式是推演大前提，地面、飞行、近地悬浮的寻路与坑洞行为不同，先确认再推演

### 波次时序

- 条目：《关卡数据结构》波次节
- 用途：理解出怪的时序逻辑

### 寻路移动

- 条目：《敌人行动与移动机制》《寻路逻辑》《移动相关理论》
- 用途：理解轨迹形态（折线、弧度、不对称）、到达时刻与检查点完成时刻

### 阻挡与受击

- 条目：《阻挡与受击判定》《阻挡底层机制》
- 用途：阻挡偏移结果、入坑可行性分析、受击判断

### 位移

- 条目：《力度与位移》《位移底层机制》
- 用途：推拉入坑的简单分析与底层原理

## 二、底层思维

以下为行动推演的基本概念与规范。

### 时空两层次

- 时间：基本认识是关卡波次信息（何时出怪、延迟、波次衔接）；精细认识在帧级别（到达帧、完成帧、入坑帧）。实际出生行为较复杂，敌人的出生帧与设定值存在偏差，因此模拟工具中以相对帧为口径（f0 = 生成帧），全局帧依赖波次时序关系与游戏内实测
- 空间：基本认识是关卡地图构造（格、通行、路线）；精细认识在坐标计算（精确位置、格边界、取整归属）
- 空间构造、波次时序从关卡数据中获取（query_level）

### 行动时序

- 帧是敌人行动的基本单位，行动逐帧推进
- 基本时序：敌人行动的每一帧会先基于当前坐标（上一帧的最终坐标）判定状态（寻路/阻挡/失衡等），再基于本帧状态计算本帧位移，进而得到本帧坐标，因此每一帧的坐标是输出结果，影响的是下一帧的推演。注意不要时序错乱
- 事件发生帧与影响生效帧是两回事：例如部署行为发生在一帧的末尾，下一帧才开始改变状态并开始发生偏移。人为操作只能插入在两帧之间，在某一帧执行操作，该帧实际已经完成了“状态判定-坐标计算”，所以影响从下一帧才开始发生
- 帧长约为 1/30 秒但略小于它：停驻 N 秒实际表现为 N×30+1 帧（如停驻 30 秒为 901 帧）

### 自由度处理

- 对于未精确测定、未解析清楚的自由度，合理地进行压缩与假设。例如模拟工具不指定出生的全局帧，而以相对帧为口径，f0 为出生帧。出生帧后的首个寻路帧在哪、避障力（三帧周期）的首个重算帧在哪，理论尚未明确解析，因此提出等效避障相位的概念：取 f1 为首个寻路帧，将多个自由度压缩为“f1 是避障周期的第几帧”，把复杂自由度转化为三种避障相位下的三种不同轨迹，对应模拟工具的 K 参数：相位为（相对帧 - K） mod 3，默认 K=1
- 分析手段选择：基于问题需求选择定性分析或精确计算，简单问题通过理论分析给出回答，稍复杂的问题借助模拟工具的事件流，帧级坐标的确定与分析则对模拟输出做数据处理
- 知识条目与模拟给出的是理论值，实际表现可能有帧级偏差：结论与假设绑定，声明偏差可能。分清偏差的存在性：如模拟采用相对帧、基于避障相位计算行进轨迹，在给定前提下不存在偏差，而全局帧则通常与设定值存在偏差，例如设定关卡开始后敌人立即出生，但实测情况经常存在帧级偏差，这也是模拟采用相对帧的原因

## 三、入坑课题

本节逐步深入机制概念分析。涉及未学习的知识条目，不必深究其中理论，理解处理哲学即可。

### 1. 入坑的本质：改变所属格

显而易见的认识：推拉可以把敌人推进坑。但阻挡偏移最多把敌人推到距阻挡位中心 0.5 格处（格边界），看起来够不着相邻的坑格，为什么仍然能入坑？

处理哲学：入坑的关键在于坐标落入哪个地块的判定域。边界点（如 x = 3.5）的归属由取整规则决定，临界值归偶数侧；坑格在偶数侧时，边界点就属于坑格。偏移到边界 + 边界归属坑格，入坑即成立，不需要跨格。

### 2. 基本偏移入坑：对齐与稳定整数坐标

阻挡偏移现象中，偏移方向 = 敌人相对阻挡位中心的方向，最多挤到 0.5 格半径处。要精确挤到边界，偏移方向必须纯水平或纯竖直。

敌人水平移动时若 y 恒定为整数（即格中心），任何时刻部署阻挡，偏移方向都是纯水平的，偏移后必落在 x 边界。这就是稳定整数坐标的价值：找到移动轴垂直方向坐标稳定为整数的时段，阻挡偏移的结果可精确确定。

敌人出生坐标通常为格中心（整数），可带出生偏移。偏移只沿一个轴向时（竖直或水平），径向偏移后恰落在该轴向的格边界，边界点归属相邻格，相邻格为坑即可直接入坑。

### 3. 路径点与寻路对路线的影响

路径点判定半径：检查点完成条件是光标进入目标点 0.05 半径内，敌人不会精确走到格子中心。完成时坐标偏离中心，转向下一目标时轨迹呈现弧度而非直角。因此转弯会使敌人两个坐标都不为整数。

路径点收敛：不同路径的敌人指向同一路径点，都会在该点附近收敛；多个同样的路径点会不断加剧收敛，最终坐标基本一致。但坐标一致不代表避障相位一致：同一坐标存在三种相位，避障生效时机不同，路线形成三种差异。

寻路算法所致的现象：

- 敌人沿 nextnode 前进，刚进入一个格子的边界处就立即转到新方向（换向点 = 首次判定为nextnode格时的坐标）；路径点目标则要接近坐标中心（0.05 半径内）才换向
- 平整化处理按先下后上、先左后右的顺序进行，等距路径的选择由处理顺序决定：几何对称的路线可能走出不对称的轨迹，本质是 nextnode 计算结果并不对称

因此，分析轨迹不能只看起点与终点；对称直觉不可靠。轨迹形态决定坐标序列，坐标序列决定阻挡偏移能否对齐、入坑解是否存在。

### 4. 惯性入坑：机制接力（海沫入坑）

现象：海沫（水月肉鸽一结局boss的俗称）较重，推力位移很小，却最终入坑。过程是三个机制接力：

- 失衡位移：向上移动接近路径点时向上推（路径点上方相邻地穴格）。推力虽小，但能把坐标送过格中心上方（自然移动不会越过格中心，阻挡偏移会向下）
- 阻挡偏移：失衡结束立即进入阻挡，向上阻挡偏移。海沫此前转弯后 x 已经不居中，偏移方向斜，竖直分量差一点到边界
- 惯性：撤退后目标自然移动，但惯性仍保留推前向上的分量，正是这点向上的惯性让海沫自己走进了坑

时序衔接（失衡与阻挡无缝、惯性的冻结与恢复）是多机制分析的基石。

### 5. 精度窗口：理论不可能中的可能

第 2 层说必须对齐才能入坑，但存在例外：坐标数值以 float32 存储（见《数值误差》），偏移后坐标落在临界值附近的窄窗口内（纵向偏差约 ±0.000345）时，存储精度使坐标同样可能判入坑格。于是理论上不可坑的路线，可能在某帧恰好满足窗口条件，抓住那一帧阻挡偏移，即可达成“理论不可能”。

入坑判定由坐标值决定，避障相位改变轨迹，在考虑的数值精度下，一点微小的变化都会影响入坑解的存在性。

### 6. 调避障轴：创造入坑解

由于精度要求极高，这种“理论不可能”的入坑解也的确极难存在。不过我们注意到，同一条路线，三种避障相位会生成三种不同的坐标序列，改变避障相位后或许能影响入坑解的存在与否。

机制：阻挡期间避障周期冻结（周期计数暂停，坐标被偏移改变）。撤退后避障从偏移后的坐标继续：相位本身没变，但相位对应的坐标序列变了，等效于换了相位。调轴的本质：偏移到哪里并不重要，关键在于避障相位改变了后续轨迹的精细坐标值。

总结：入坑课题的本质在于坐标调整，前提是有入坑条件（地图中无坑自然不行），基本思路是推拉，阻挡偏移和惯性则是补充。

本节从入坑课题出发，将不同知识条目应用于问题分析上，对 PRTS 而言，求解不是任务目标，推演与解释才是基本目标，所以关键不在于学习解法思路——作战规划由博士完成，而在于基于处理哲学辅助推演及现象解释。

## 四、模拟工具使用

- 使用场景：需要模拟敌人行动路线（自然移动、人为影响下的移动）时
- 行为注入：注入额外的阻挡位部署事件、推拉作用事件，阻挡偏移与失衡位移在模拟中取匀速运动，可能与实际不符
- 避障相位调节：改变默认避障相位，用于研究、验证
- 自定义：自定义路线、预置障碍物
- 计时起点：为特殊的停驻计时设置起点（模拟内出生帧恒为 f0，计时起点通常取负帧）
- 能力边界：仅支持地面行动（WALK），模拟只考虑单个敌人的路线

### 参数语法

- k：避障相位参数（默认 1）。相位 = (相对帧 - k) mod 3，k=1 时出生帧下一帧是避障第 0 帧。研究避障轴差异时按实测标定
- inject：行为注入，分号分隔多条，同帧最多一个 push；多个 block 允许但 at 不得同格。设定帧仅为触发信号，不影响该帧状态，下一帧起生效
  - push@帧:dir=(dx,dy),dist=距离,dur=失衡帧数：设定帧按当前状态执行，下一帧起匀速失衡位移；失衡覆盖一切（含旧失衡、偏移、稳定），失衡中再 push 则新参数覆盖旧
  - block@帧:at=(gx,gy),dur=帧数：部署阻挡位，事件生命周期=部署帧到撤退帧（dur 为总帧数，0 则零长度无效果）。期间每帧帧首基于上一帧末坐标判定：实体所在格在阻挡位十字五格（阻挡格+上下左右）内且距离平方<0.25 触发 6 帧径向偏移、<=0.49999037 稳定阻挡；范围外不判不报错。先到先得归属（已归属不切换），偏移中不重复触发，偏移可被 push 覆盖，失衡结束后重新判定
  - block@帧:pos=(x,y),dur=帧数：pos 模式预计算偏移目标（如旋转偏移），触发帧（设定帧下一帧）必须不处于失衡，否则无效并输出提示、注入忽略；与 at 互斥
- route：自定义路线 DSL，分号分隔，参数内逗号。START(x,y[,ox,oy]);MOVE(x,y[,ox,oy]);WAIT(s);WAIT_GLOBAL(s);WAIT_FRAGMENT(s);WAIT_WAVE(s);DISAPPEAR();APPEAR(x,y);END(x,y)。不填则用数据库路线
- timeAxis：三种计时起点（相对帧，默认 0=f0），供 WAIT_GLOBAL/FRAGMENT/WAVE 使用：global=全局时间轴起点、fragment=段时间轴起点、wave=波时间轴起点
- 注：阻挡结束时若敌人攻击动画未结束，则不会立即进入寻路状态，模拟程序中未考虑这一点，严格模拟需要将阻挡时间与实际敌人非寻路时间对齐，以实现等效

### 帧级log格式

sim_path 的帧级 log（工作区 sim_logs/，路径见工具输出 log: 行）是 JSONL，三段：首行 meta（关卡/路线/结束等汇总）→ 中间逐帧 frame（坐标状态流，可达数千行，勿整读）→ 尾部 event（事件文本 + 帧号）。

如需写绘图脚本，可先确认结构：读前 3 行 ，再读末尾 10~20 行，头尾样本即可确定键名形态。绘图：轨迹取 frame 的 x/y，事件标注按 event 的 f 回查坐标，底图用 query_level 地图输出。
