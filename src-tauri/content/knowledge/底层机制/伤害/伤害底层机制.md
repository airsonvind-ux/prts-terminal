## 定位

本条目解析一次攻击在代码层面的完整处理流程。数值计算见《伤害计算基本公式》，伤害属性枚举见《伤害分类表》，红字与伤判效果的具体规则见各自条目。

## 攻击处理流程（9 步事件链）

一次攻击是携带伤害（治疗）量与属性的数据包（modifier），从发出到结算经历来源实体与目标实体事件交替的流程：

| 步骤 | 事件 | 角色 | 应用举例 |
|:--|:--|:--|:--|
| 1 | 来源实体事件：ON_CALCULATE_DAMAGE | 获取 modifier 各项属性，计算伤害并生成 modifier | 攻击倍率调整 |
| 2 | 准备向目标实体应用 modifier | 检查 modifier 是否被 cancel，被取消则流程终止 | |
| 3 | 目标实体事件：ON_BEFORE_APPLYING_MODIFIER | | |
| 4 | 来源实体事件：ON_OUTPUT_MODIFIER | 检查来源有效性 | 造成治疗倍率调整 |
| 5 | 检查 modifier 目的，为伤害时执行来源实体事件 ON_OUTPUT_DAMAGE | | 伤害倍率调整 |
| 6 | 目标实体事件：ON_APPLYING_MODIFIER | | 受治疗倍率调整 |
| 7 | 执行 On_Take_Damage / On_Take_Heal | 取消隐匿/无敌状态下的攻击；取消试图非强制治疗不可治疗单位的治疗；检测 modifier 是否被 cancel；处理反伤、闪避、抵挡、护盾等伤判效果 | 未被 cancel 时对目标应用 modifier |
| 8 | 应用成功后：目标实体事件 ON_APPLIED_MODIFIER | | |
| 9 | 检查 modifier 目的，为伤害时执行来源实体事件 ON_AFTER_OUTPUT_DAMAGE | | 成功造成伤害为条件的效果触发判定 |

规律：倍率类修正集中在应用前（步骤 1、4、5、6），拦截类判定集中在应用时（步骤 7），效果触发集中在应用后（步骤 8、9）。

cancel 检查出现两处：步骤 2 为应用前的源头检查，步骤 7 为生效前的目标侧拦截，任一环节被取消则 modifier 不再继续。

## 关键判定原理

### 位掩码远近战判定

近战/远程属性以两位二进制存储：00 无、01 近战、10 远程、11 近+远。特效生效检查用“条件与数据做与运算，结果无变化即判定成功”：

- 条件近战 & 数据近战（01 & 01 = 01）无变化，判定成功
- 条件近战 & 数据远程（01 & 10 = 00）有变化，判定失败

00 空值的特例：01 & 00 = 00 无变化，会被误判为近战，伤害类型为 00（无）的固定伤害因此会触发近战类特效。有弹道的攻击固定为 10、无弹道固定为 01，无弹道的远程攻击也会被近战类特效命中。

### 顺序结算（buffContainer）

同一行动节点内的多个效果按 buffContainer 中的顺序结算，绝大部分时候即添加顺序，各效果互不调用、各自独立修改 modifier：

- 先屏障后易伤：屏障先抵消部分伤害，伤害倍率只作用于抵消后的值，屏障吃不到加成
- 先易伤后屏障：modifier 先被放大，屏障扣减同样被放大

以补充层数方式获得的护盾不改变获取顺序，会保持原有的结算位置。

### 预计算伤害与计算后伤害

- 预计算伤害：伤害计算与造成逻辑分离，通常没有 ON_CALCULATE_DAMAGE 事件，modifier 在攻击前预先算好。所有使用缓存攻击力的伤害均属此类，因此没有完整计算流程（红字期望伤害直接取攻击力属性）
- 计算后伤害：没有伤害计算逻辑，连防御/抗性和攻击力倍率增减都无法处理

### 弱点伤害

弱点伤害在 ON_CALCULATE_DAMAGE 事件中处理。当伤害为物理或法术时，临时计算理论物理伤害与理论法术伤害各一次，仅计入攻击力、攻击力倍率、攻击力附加值、物理/法术贯穿、目标防御/法抗，不计入其余任何数据与效果（伤判效果、重设伤害效果等），也不额外触发伤害计算事件。两者近似相等（忽略精度误差）则不改变伤害类型，否则转换为数值更高的一方，再继续后续伤害计算。

## 流程中的两个位置

- 伤判效果：位于步骤 7 的拦截判定序列中，在计算完防御/法抗之后、应用 modifier 之前，按事件优先级与获取顺序逐个处理（规则见《伤判效果》）
- 红字判定：伤害应用成功后，由显示层按红字规则判定是否弹出（规则见《伤害红字》）
