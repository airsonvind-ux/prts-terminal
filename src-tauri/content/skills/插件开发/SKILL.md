# 插件开发

插件是一个独立进程，通过 stdio 上的 `Content-Length` 帧与宿主对话。宿主给你的
不是库，是一组**能力**（函数）；工具由你在 `initialize` 里声明，模型看见的就是
这些工具。

## 先判断要做什么

| 场景 | 去哪 |
|---|---|
| 从零写一个能跑通的插件 | 手册《01 快速开始》，照模板改 |
| 改 `plugin.json`、加参数、改 id | 手册《02 manifest》 |
| 帧怎么封、方法怎么回、错误码怎么给 | 手册《03 协议》 |
| 要读方舟数据 / 存文件 / 起 MAA | 手册《04 能力》 |
| 工具怎么命名、描述怎么写、返回什么 | 手册《05 工具设计》 |
| 启动、就绪、超时、崩溃、五状态 | 手册《06 生命周期》 |
| 附带技能、提示词里怎么显示 | 手册《07 技能与提示词》 |
| 打包、版本、发布前检查 | 手册《08 发布》 |
| 校验器输出怎么读、为什么起不来 | 手册《09 排错》 |

手册随应用发布，在资料目录的 `plugin-dev/` 下（设置 → 关于 → 打开资料目录）。
先读《01》，再按需翻。

## 五条硬约定

1. **stdout 只能写帧。** `print`、日志库、依赖的 banner 都会污染管道，宿主看到
   非帧内容会判故障。调试写 stderr，或发 `log` 通知。
2. **工具名不带前缀。** 你在 `initialize` 里声明 `hello`，宿主注册成
   `my_plugin_hello`；名字本身要匹配 `^[a-z][a-z0-9_]{0,63}$`。
3. **能力必须先声明。** `plugin.json` 的 `capabilities` 里没有的键，`host.call`
   一律回 `-32000`。多声明会在安装页展示给用户，别乱要。
4. **先握手再干活。** 收到 `initialize` 之前不要发任何请求；收到 `shutdown`
   就收场退出，别等宿主杀。
5. **安装只认文件夹。** 校验用 `plugin_check <目录>`，八项全 PASS 再装；zip 要
   先解压。

## 工作顺序

1. 明确这个插件**替模型做哪件事**，对应成几个工具（一个工具一个动作）；
2. 写 `plugin.json`：id 小写连字符、`requires.protocol: 1`、只声明真要用的能力；
3. 照最接近的模板（Python 或 Rust）搭骨架，先让 `initialize` + 一个 `echo`
   工具跑通；
4. 用 `plugin_check` 卡一遍，再进应用里装、在新对话里调；
5. 工具描述写清「做什么 / 何时用 / 返回什么」，需要时补技能（手册 07）；
6. 发布前按《08》的自检清单过一遍。

## 容易踩的坑

- id 里出现大写或下划线 → 十二条校验第 1 条就拒；
- 忘了 `requires.protocol`，或写成 `2` → 第 6 条拒；
- 能力名用了旧词 `fs.pluginData` / `agent.query` / `network` → 现在是
  `fs.plugin` / `query.call` / `net.request`（未开放）；
- 工具描述写「查询数据」→ 模型不知道什么时候该用，写成「按名字查干员的职业
  与技能；用户提到具体干员时用」；
- 在插件目录里放与解释器同名的可执行文件 → 裸名入口会优先命中它。

## 边界

- 插件是任意代码，宿主不做沙箱；能力限制的是宿主借给你的函数，不是你的进程；
- 不要读插件目录以外的文件，不要绕过 `fs.plugin` 的路径校验；
- 业务逻辑放你自己进程里，宿主只提供数据与文件这类原语。
