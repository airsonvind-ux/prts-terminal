# 09 排错

先跑校验器，再谈别的：

```bash
plugin_check ./my-plugin
```

## 怎么读输出

```text
[1] PASS  目录与 plugin.json
[2] PASS  manifest 十二条校验
[3] FAIL  entry.exe 解析
          插件目录里没有 hello.py，PATH 里也找不到 hello
          确认文件名拼写；解释器要先能用 `python --version` 跑通
[4] --    进程启动（前一项失败，跳过）
```

- `[n]` 是检查序号，1–8 顺序固定；
- 状态列四格：`PASS`、`FAIL`、`--`（跳过）；
- FAIL 下面缩进两行：**第一行原因，第二行怎么改**；
- `--` 表示前一项没过，这项没跑；原因写在标签后的括号里。

`--json` 给机器读：

```json
{"plugin":"./my-plugin","ok":false,
 "checks":[{"id":3,"status":"fail","detail":"…","fix":"…"}]}
```

退出码：`0` 全过（或跳过），`1` 有失败，`2` 参数写错。

## 八项检查

| # | 检查 | 它到底做了什么 |
|---|---|---|
| 1 | 目录与 plugin.json | 目录在不在、`plugin.json` 能不能解析 |
| 2 | manifest 十二条校验 | 字段、id、版本、能力名 |
| 3 | entry.exe 解析 | 目录里有就用它，否则按 PATH 找裸名 |
| 4 | 进程启动 | 起进程，1 秒后还活着 |
| 5 | initialize 往返 | 发 `initialize`，5 秒内收到合法应答 |
| 6 | 未知工具名 | 调一个不存在的工具，应回 `-32602` |
| 7 | shutdown 收场 | 发 `shutdown`，3 秒内退出 |
| 8 | stdout 只有帧 | 期间 stdout 没有非帧内容 |

## 五类常见失败

### 1. 目录里没有 plugin.json

```text
[1] FAIL  目录与 plugin.json
          读不到 /my-plugin/plugin.json：系统找不到指定的文件
          确认选的是插件目录本身，zip 请先解压
```

多半是拖进来的是外层大文件夹，或者 zip 没解压。安装界面也只认文件夹。

### 2. manifest 不合法

```text
[2] FAIL  manifest 十二条校验
          id 不合法：My_Plugin
          只能用小写字母、数字、连字符，且以小写字母开头
```

按 [02-manifest](02-manifest.md) 的十二条表逐条对。最常见的三个：id 大小写、
`requires.protocol` 没写、能力名拼错（`fs.pluginData` 是旧名字，现在是
`fs.plugin`）。

### 3. 入口找不到

```text
[3] FAIL  entry.exe 解析
          入口不存在：/my-plugin/hello
          确认 plugin.json 的 entry.exe 是否相对插件目录
```

- Python：`"exe": "python"` 要能在命令行里跑通 `python --version`；
- Rust：可执行文件要**拷到 `plugin.json` 旁边**，不是留在构建目录里；
- 文件名带空格或中文时，确认路径拼对了。

### 4. 起来了但没握手

```text
[4] PASS  进程启动
[5] FAIL  initialize 往返
          5 秒内没有读到第一帧
          确认程序读 stdin 后回了 {"jsonrpc":"2.0","id":1,"result":{…}}
```

常见原因：

- 程序把欢迎信息打印到了 stdout——那会被当成坏帧，检查 8 也会失败；
- 只处理了 `tool.call`，忘了 `initialize`；
- 阻塞在读参数或连数据库，没进循环；
- 帧格式写错：`Content-Length` 后面少一个空行。

### 5. stdout 被污染

```text
[8] FAIL  stdout 只有帧
          读到非帧内容：hello from plugin
          调试输出请写 stderr 或发 log 通知
```

`print`、日志库默认输出、某个依赖的 banner，都可能掉进 stdout。Python 里把
调试改成 `print(..., file=sys.stderr)`；Rust 用 `eprintln!`。

## 装上了但用不了

### 列表里没有这个插件

看「未登记」小节：目录里有 `plugin.json` 但读不出来时，会单独列出来并给
原因。装错层级（多套了一层文件夹）是最常见的情况。

### 状态是「加载失败」

点开看原因。这类失败进程根本没起，改完 manifest 要重新安装。

### 状态是「进程退出」

握手失败，或调用超时被杀。点「重试」再试一次——自动重启只试一次，第二次失败
就停在故障状态，等这个按钮再给你一次机会。

### 对话里说「插件 X 已停用」

- 插件被关了：打开开关，**新建对话**；
- 或者旧对话用的是旧工具快照：新建一个对话。

### `host.call` 返回 -32000

没在 `capabilities` 里声明那个能力。改 manifest 后重新安装（改文件不会热
生效）。

## 还是不行

带上这些去问：

1. `plugin_check` 的完整输出；
2. 插件列表里的状态与原因；
3. `plugin.json`；
4. 平台与运行时版本（`python --version`）。

有这些，大部分问题一眼能定位。
