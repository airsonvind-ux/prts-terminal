# 08 发布

插件就是一个文件夹。发布 = 把这个文件夹交给别人，对方在自己的机器上校验、
安装。

## 打包

```text
my-plugin-0.2.0/
├─ plugin.json
├─ hello.exe            （或 hello.py）
├─ skills/…
└─ README.md
```

打成一个 zip 分发，但**安装只认文件夹**：对方要先解压，再把解压出来的目录
拖进设置 → 扩展。手册与安装界面都会这么提示。

打包前删掉：

- 构建目录（`target/`）、依赖缓存、你本机的绝对路径；
- `.git/`、测试数据、日志；
- 任何密钥、token。

## 版本

`plugin.json` 的 `version` 是插件自己的版本，语义化：修 bug 改 PATCH，加工具
或加参数改 MINOR，改工具行为或删参数改 MAJOR。

两条约束：

- **`id` 永远不变**。它决定数据目录与开关记录，改了等于换一个插件；
- **`requires.app`** 写你真正用到的最低应用版本；不写就是「谁的能装都行」。

协议版本 `requires.protocol` 现在固定 `1`，不要改。

## 升级怎么发

应用没有「原地升级」按钮：装同一个 id 会被拒绝（提示先卸载旧的）。

正确的升级流程：

1. 卸载旧版，**不要勾**「同时删除它的数据」；
2. 安装新版目录；
3. 新对话里生效。

数据目录 `plugin-data/<id>/` 因此保留下来。如果你的新版本改了数据格式，自己
做一次迁移——宿主不会替你迁。

## 发布前自查

- [ ] 从**干净拷贝**跑一遍 `plugin_check`，八项全 PASS（不要在自己的开发目录
      里跑完就发，那里可能多出缓存文件）；
- [ ] 写清运行前提：Python 插件要 `python` 在 PATH 里；Rust 插件把可执行文件
      放在 `plugin.json` 旁边，并说明支持哪些平台；
- [ ] 在另一台机器上装一遍——不是你的开发机；
- [ ] README 里写：这个插件做什么、要什么能力、怎么装、怎么卸、数据存哪；
- [ ] 检查 `capabilities` 没有多声明：多要的能力在安装确认页会显示出来，用户
      会问。

## 关于安全

插件是任意代码，宿主不沙箱你。能力边界只约束**宿主借给你的函数**，不约束
你的进程本身。

所以：

- 只声明真正用到的能力；
- 不要试图从别的路径读文件——用户会在安装页看到你的能力清单，越权行为比
  少一个功能更伤信任；
- 处理用户数据（对话、ID）时按敏感数据处理，不要写进日志。

## 拿到别人给你的插件

1. 解压到任意位置；
2. 跑一次 `plugin_check <目录>`，看八项是否全 PASS；
3. 装之前扫一眼目录里有没有多余的可执行文件——`entry.exe` 是裸名时，目录里
   同名的文件会优先命中；
4. 设置 → 扩展 → 安装，确认卡片上的能力清单是否合理。

## 反馈问题时带上这些

- `plugin_check` 的完整输出（文本版就行）；
- 插件列表里这一行的状态与原因文本；
- `plugin.json`（去掉敏感字段）；
- 你的平台与 Python/运行时版本。
