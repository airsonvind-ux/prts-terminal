# 06 生命周期

插件从「装」到「卸」只有一条主线：**装在目录里 → 应用启动时拉起 → 握手 →
用工具 → 退出时收场**。中间任何一步失败，插件进故障或失败状态，但不影响
别的插件，也不影响应用本身。

## 启动

应用启动时扫两处：随包目录与应用数据目录。每个插件按目录名排序依次处理：

1. 读 `plugin.json`；
2. 跑十二条校验；
3. 看 `plugins.json` 里是不是被停用了；
4. 拉起进程、发 `initialize`、等 10 秒。

第 1–3 步失败是**加载失败**：进程根本没起，列表里显示原因。第 4 步失败是
**进程退出**：进程起过但没握手成功。

## 五种状态

| 状态 | 列表里显示 | 含义 |
|---|---|---|
| `starting` | 启动中 | 进程刚起，还没握手完 |
| `loaded` | 正常 | 握手成功，工具可用 |
| `failed` | 加载失败 | manifest 或安装有问题，进程没起来 |
| `faulted` | 进程退出 | 崩了，或调用超时被杀 |
| `disabled` | 已停用 | 用户关了它 |

`failed` 会带一条原因（比如「manifest 校验失败：…」），`faulted` 会带一条
原因（比如「调用超时且 cancel 没有回音」）。

## 崩了之后

**不自动重启。** 崩溃循环比崩溃本身更糟：一个每次都崩的插件会把资源吃光。

规则是：

- 第一次崩 → 标记 `faulted`；
- 之后再调它的工具 → 尝试重新拉起**一次**；
- 拉起成功 → 回到 `loaded`，工具照常；
- 又失败 → 锁死，返回「插件已故障（重启 PRTS 后恢复）」，直到你重试或重开应用。

手动点「重试」或把开关关掉再打开，等于清掉这条锁，允许再试一次。

## 调用超时

`tool.call` 超出时限（工具定义的 `timeoutMs`，默认 60 秒）：

1. 宿主发 `cancel` 通知；
2. 给 2 秒收场：你回原来的 `id`（结果或 `-32002`）都算收场；
3. 没回音 → 杀进程，标记 `faulted`。

想避免被杀，就在时限内返回；确实要长跑，参考
[05-工具设计](05-工具设计.md) 的「拆成两个工具」。

## 停用与启用

**停用**（对话空闲时才能做）：

- 宿主先摘掉你的工具，再杀进程；
- 正在进行的对话不会受影响——它用的是启动时冻结的工具列表，旧对话里调用
  已停用的工具会收到「插件 X 已停用」；
- 你的技能也不再进索引，**新对话**里看不到；
- 数据目录与临时目录都保留。

**启用**：重新走一遍启动流程（读 manifest、拉起、握手）。失败就进 `failed`
或 `faulted`，原因照常显示。

停用/卸载/重试在对话处理中会被后端拒绝——它们会打断正在跑的任务。启用与
安装不受限制，只是要等新对话（或压缩之后）才生效。

## 退出

应用退出时：

1. 给每个插件发 `shutdown`，等它退（最多 2 秒）；
2. 没退的杀掉；
3. 删掉 `plugin-temp/` 下所有临时目录。

收到 `shutdown` 后的正确做法：回一帧 `result`，然后 **退出码 0** 结束进程。
不要在这时候去做耗时清理，2 秒不够会被杀。

## 卸载

- 删插件目录、删临时目录、从 `plugins.json` 去掉开关项；
- 数据目录默认保留，勾选「同时删除它的数据」才删；
- 内置插件不能卸载。

## 你的进程要守的几条

1. **stdout 只写帧**：调试用 stderr；
2. **读线程不要阻塞**在业务逻辑上，否则 `host.call` 与 `cancel` 都收不到；
3. `initialize` 之前不要发任何请求——宿主还没准备好；
4. 收到 `shutdown` 就退，别挂着；
5. 退出码非 0 会被当成崩溃，进 `faulted`。
