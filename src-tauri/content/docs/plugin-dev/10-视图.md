# 10 · 视图

工具可以让模型**读文字**，也可以让用户**看东西**。这两件事分开：

- `content` 给模型读，原样进上下文；
- `view` 给用户看，宿主渲染成一张卡片，**不进上下文**。

所以 `content` 永远不能省。视图再漂亮，模型看到的也只有 `content`。

## 返回形状

`tool.call` 的 `result` 有两种写法，字符串是老写法：

```json
{ "content": "查到 3 张图片。" }
```

```json
{
  "content": "查到 3 张图片。",
  "view": {
    "kind": "html",
    "title": "图片索引",
    "height": 120,
    "html": "<ul><li>1.png</li><li>2.png</li></ul>"
  }
}
```

对象形态下 `content` 必填且非空。缺了或给了空串，宿主按 `-32602` 判错，
**不会**回落到「把整个 JSON 塞给模型」——那样视图反而会从后门进上下文。

## 三种视图

| kind | 你给什么 | 宿主怎么处理 |
|---|---|---|
| `html` | `html` 字段里的 HTML 源码 | 落盘成文件，在沙箱 iframe 里渲染 |
| `image` | `path`，插件目录内的相对路径 | 复制到会话目录，按图片显示 |
| `doc` | `path` + `mime` | 复制到会话目录，点开用系统程序打开 |

公共字段：

| 字段 | 必填 | 说明 |
|---|---|---|
| `kind` | 是 | `html` / `image` / `doc` |
| `title` | 是 | 卡片标题，≤ 60 字。缺了或超长判错 |
| `height` | 否 | 建议高度，宿主限制在 40–160px，缺省 120 |

`html` 的内容上限是 **64 KiB**（UTF-8 字节）。超了不算致命错误：宿主把它降级成
纯 `content`，并在末尾追加一句「视图内容超过上限，只保留文字」。也就是说，
**超限的视图不会显示**，模型读到的是原 content。

`image` / `doc` 的 `path` 必须落在插件目录内，越界（`..`、绝对路径、盘符）
一律判错。视图落盘后，卸载插件也还能回看旧对话。

## 沙箱里能做什么

`html` 视图跑在一个**不透明源**的 iframe 里：

- 不能发网络请求（`connect-src 'none'`）；
- 拿不到 cookie、localStorage（访问会抛 `SecurityError`）；
- 碰不到宿主页面（`parent.document` 是 null）；
- 可以用内联样式与内联脚本。

视图是给用户看的静态产物。要跟宿主说话，只能走下面四个原语。

## 四个交互原语

在视图里向父页面发消息：

```js
parent.postMessage(
  { source: "prts-view", type: "prompt", text: "把第 2 张图放大" },
  "*"
);
```

| type | 效果 |
|---|---|
| `local` | 什么也不做，视图自己的交互 |
| `prompt` | 把 `text` 作为一次用户输入交给对话 |
| `call` | 调用你自己的某个工具（`tool` + `args`） |
| `toast` | 只弹一条提示（`text`） |

规则：

- `source` 必须是 `"prts-view"`，否则丢弃；
- `text` 上限 2000 字，超了拒绝；
- 每张视图每分钟最多 10 次，超了丢弃；
- 焦点在输入框时，`prompt` 只填草稿，不替你发出去；
- 没有进行中的对话时，`prompt` 与 `call` 都退化成草稿——视图不能替用户开一轮对话。

宿主会在消息前标上来源，模型看到的是「来自《图片索引》的交互：把第 2 张图放大」。
`call` 发起的工具调用，过程卡里标「由视图」，上下文里也带同样的来源。

`call` 只能调**你自己注册过**的工具。想调宿主工具，请在插件里包一层，
由你的工具去用能力。

## 校验器

```powershell
plugin_check .\my-plugin --call show_card --args '{\"limit\":3}'
plugin_check .\my-plugin --call show_card --render-view preview.html
```

- `--call` 真调一次工具，按宿主同一套规则检查 `content` / `view`；
- `--args` 给它参数，缺省 `{}`；
- `--render-view` 把 `html` 视图写成一个可单独打开的预览页（外壳与宿主一致，
  同样是 `sandbox="allow-scripts"`）。

通过时打印 `content` 与视图的 kind/title/height；不通过时以退出码 1 结束，
并说明是「结果不合法」还是「视图越界」。

## 常见错误

| 现象 | 原因 |
|---|---|
| `-32602`，`对象结果缺少 content` | 只给了 `view`，没给 `content` |
| `content 是空的` | 给了 `content: ""`——空串也不允许 |
| `view.title 超过 60 字` | 标题写成了整段描述，截短 |
| `view.path 越出插件目录` | 用了绝对路径或 `..` |
| 视图显示「这块视图已不可用」 | 落盘文件被删了（手工清理过会话目录） |
| 视图里点了没反应 | `source` 不是 `"prts-view"`，或超过 10 次/分 |

## 什么时候该用视图

适合：表格、列表、图表、地图、图片索引——**结构化、看一眼就懂**的东西。

不适合：把正文再排版一遍、放一句「操作成功」、做需要多步操作的界面。
视图是对话里的一张卡，不是一个小程序。
