# 03 协议

宿主与插件之间是一条 stdio 管道，双向都是「一帧一个 JSON」。

## 帧格式

```text
Content-Length: <正文字节数>\r\n
\r\n
<UTF-8 编码的 JSON>
```

- 头部一行 `Content-Length`，大小写不敏感，其它头会被忽略；
- 正文是 UTF-8 JSON，单帧上限 8 MiB；
- **stdout 上只能有帧**。`print("调试")` 会让宿主读到非帧内容，判为故障并杀
  进程；调试输出走 stderr 或 `log` 通知。

Python 里最省事的两个函数：

```python
def read_frame(stream):
    length = None
    while True:
        line = stream.readline()
        if not line:
            return None
        line = line.strip()
        if not line:
            break
        if line.lower().startswith(b"content-length:"):
            length = int(line.split(b":", 1)[1].strip())
    body = stream.read(length)
    return json.loads(body.decode("utf-8"))


def write_frame(stream, message):
    body = json.dumps(message, ensure_ascii=False).encode("utf-8")
    stream.write(b"Content-Length: %d\r\n\r\n" % len(body))
    stream.write(body)
    stream.flush()
```

## 一次完整的对话

```text
宿主 → {"jsonrpc":"2.0","id":1,"method":"initialize",
        "params":{"protocol":1,"hostVersion":"0.1.1","pluginId":"my-plugin"}}
插件 → {"jsonrpc":"2.0","id":1,"result":{"protocol":1,"capabilities":[],
        "tools":[{"name":"hello","description":"打招呼","parameters":{...}}]}}

宿主 → {"jsonrpc":"2.0","id":2,"method":"tool.call",
        "params":{"name":"hello","args":{"name":"博士"},"deadlineMs":60000}}
插件 → {"jsonrpc":"2.0","id":2,"result":"你好，博士！"}

宿主 → {"jsonrpc":"2.0","id":3,"method":"shutdown","params":{}}
插件 → {"jsonrpc":"2.0","id":3,"result":null}   然后退出（退出码 0）
```

`id` 由发起方分配，应答原样带回。插件主动发给宿主的请求（`host.call`）自己
分配 id，宿主按 id 回。

## 宿主 → 插件

| 方法 | 参数 | 说明 |
|---|---|---|
| `initialize` | `protocol`、`hostVersion`、`pluginId` | 必须在 10 秒内回。`tools` 是**唯一**的工具面来源 |
| `tool.call` | `name`、`args`、`deadlineMs` | `name` 是**没加前缀**的名字 |
| `shutdown` | 无 | 回一帧后退出，退出码 0 |
| `cancel` | `id` | 通知（无 id）：宿主已放弃 `id` 这次调用 |

`initialize` 回报的 `capabilities` 只作诊断，不参与授权——授权看 manifest
里声明了什么、宿主登记了什么。

## 插件 → 宿主

### `host.call`

```json
{"jsonrpc":"2.0","id":10,"method":"host.call",
 "params":{"key":"query.call","args":{"tool":"query_operator","args":{"name":"能天使"}}}}
```

宿主回：

```json
{"jsonrpc":"2.0","id":10,"result":{...}}
{"jsonrpc":"2.0","id":10,"error":{"code":-32000,"message":"没有授权的能力：query.call"}}
```

只能调用 manifest 里声明过、且宿主确实登记了的能力。四个能力的参数与返回见
[04-能力](04-能力.md)。

### `log`

```json
{"jsonrpc":"2.0","method":"log","params":{"level":"info","text":"开始处理"}}
```

通知，不需要回。写进宿主的日志，不显示在对话里。

## 错误码

| 码 | 含义 | 什么时候用 |
|---|---|---|
| -32600 | 请求不合法 | 缺 method、id 类型不对 |
| -32601 | 方法不认识 | 收到了没实现的方法 |
| -32602 | 参数不对 | 工具名不认识、args 缺字段 |
| -32000 | 能力被拒 | `host.call` 用了没声明的能力 |
| -32001 | 超时 | 宿主侧判定，插件不需要发 |
| -32002 | 已取消 | 收到 `cancel` 后对原 `id` 回这个 |
| -32010 | 插件故障 | 插件内部错误，宿主会标记故障 |

**-32601 与 -32602 别混**：工具名属于参数（-32602），只有 method 不认识才
是 -32601。

## 超时与取消

- `initialize` 10 秒不回 → 插件被判故障；
- `tool.call` 的时限取工具定义里的 `timeoutMs`（默认 60000），宿主下发的
  `deadlineMs` 是权威值；
- 超时后宿主先发 `cancel`，给你 2 秒收场；没回音就杀进程并标记故障。

长时间任务要么在时限内返回，要么自己拆成多步。**不要**在 `tool.call` 里同步
等一个永远不来的东西——那会连累整个插件的后续调用。

## 并发

宿主是「读线程只分派、不在读线程里等别人」：它等你的 `tool.call` 应答时，你
发来的 `host.call` 照样会被处理。你的实现也建议照这个来——一边处理工具调用，
一边还能读出宿主发来的帧。
