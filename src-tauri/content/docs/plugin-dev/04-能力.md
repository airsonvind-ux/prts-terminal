# 04 能力

能力是宿主借给插件的**宿主函数**。插件不能直接读应用内部状态，只能调用宿主
登记过的能力；每一条都要在 `plugin.json` 的 `capabilities` 里先声明。

## 先说边界：能力不限制你自己的进程

插件是一个独立进程。你能读哪些文件、能不能连网、能不能起子进程，取决于操作
系统给你的权限和用户的机器状态——`capabilities` 不参与这些。

能力只约束**宿主的服务**：方舟数据库、MAA 桥、宿主替你管的目录。想用这些才
要声明；自己扫一个目录、自己解一张 PNG、自己读写用户给的路径，不需要声明任
何能力，`capabilities` 留空就是合法的。

一句话：`capabilities` 回答的是「我要用宿主的什么」，不是「我被允许做什么」。

```json
"capabilities": ["query.call", "fs.plugin"]
```

声明的名字必须是已知能力，否则 manifest 校验第 8 条会拒绝加载。调用了没声明
的能力，宿主返回 `-32000`。

## 现有四个能力

| 能力 | 用途 | 需要用户授权 |
|---|---|---|
| `query.call` | 只读查询方舟数据（干员、关卡、敌人、材料……） | 否 |
| `fs.plugin` | 读写插件自己的数据目录 | 否 |
| `fs.temp` | 读写插件自己的临时目录（应用退出时清空） | 否 |
| `maa.bridge` | 起停 MAA 桥进程 | 否 |

现在的四个能力都不需要用户点同意；将来出现需要授权的（比如发网络请求），
安装时会多一步确认。

## query.call：只读查询

```json
{"key":"query.call","args":{"tool":"query_operator","args":{"name":"能天使"}}}
```

- `tool` 只能是宿主列出的只读工具（干员、关卡、敌人、材料、时间……）；
- `args` 是那个工具自己的参数，原样转过去；
- 返回是该工具的标准输出（结构化数据），不是自然语言；
- 不允许调别的插件的工具——防止插件互相递归。

适合「查一条事实再加工」。不适合批量拉全表：一次一件事，别把工具当数据库。

## fs.plugin：自己的数据目录

根目录是 `plugin-data/<你的 id>/`，只能碰这个子树。

| op | 参数 | 返回 |
|---|---|---|
| `read` | `path` | `{data, bytes}`（UTF-8 文本） |
| `write` | `path`、`data` | `{bytes}` |
| `list` | `path`（可空 = 根） | `{entries:[{name, kind, bytes}]}` |
| `stat` | `path` | `{exists, kind, bytes}` |
| `delete` | `path` | `{}`（只删文件与空目录） |
| `purge` | `confirm: true` | `{}`（清空整个目录） |

`path` 必须相对、不能含 `..`、不能是绝对路径或盘符；指向符号链接会被拒绝。
`read` 只支持 UTF-8 文本，二进制先自己转 base64。

写入是**覆盖**，没有追加模式；要追加就整读、拼好、再写。

## fs.temp：临时目录

根目录是 `plugin-temp/<你的 id>/`，应用退出时整体删除。

op 与 `fs.plugin` 相同，只是没有 `purge`，另有 `clear`（清空自己的临时目录）。

## maa.bridge：MAA 桥进程

```json
{"key":"maa.bridge","args":{"op":"ensure"}}
```

| op | 返回 |
|---|---|
| `ensure` | `{state, port, error}`，进程刚起或已在跑 |
| `status` | `{state, port, error}` |
| `shutdown` | `{state, port, error}` |

`state` 四种：`starting`（刚拉起）、`running`（存活）、`stopped`（已退出）、
`unavailable`（起不来，`error` 里是原因）。

`ensure` **只起进程、不建立连接**，然后立刻返回端口：MAA 桥只接受一次连接，
宿主不会替你先连上去探活。拿到 `port` 之后由你自己连。

这个能力只给确实要和 MAA 打交道的插件用；普通插件用不上。

## 常见的两种失败

### 没声明就调用

```text
error: {"code":-32000,"message":"没有授权的能力：fs.plugin"}
```

声明加进去，重装或重启应用。

### 能力名写错

manifest 校验第 8 条会直接指出是哪一条不认识——注意大小写与点号，是
`fs.plugin` 不是 `fs.pluginData`。
